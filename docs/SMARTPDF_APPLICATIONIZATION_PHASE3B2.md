# SmartPDF Applicationization — Phase 3B.2: Atomic Multi-Span Native Text Mutation

## 1. Overview & Problem Statement

In real-world PDF documents generated by tools such as LaTeX, InDesign, Word, and specialized PDF creators, visually contiguous words and headings are frequently split across multiple PDF content stream operators (`Tj` and `TJ` arrays) due to micro-kerning, hyphenation, or glyph clustering.

For example, a title like:
```text
"StarOrion-X: Architectural Renaissance for Low-Resource State-of-the-Art Language Modeling"
```
often consists of dozens of discrete text-show operations (e.g., 29–36 operations where `"Architectural"` is split across `["Arch", "itect", "ural"]`).

Prior to Phase 3B.2:
1. Selection grouped entire multi-line headings into a single uneditable visual block (`GROUP_SELECTION_ONLY`).
2. Single-span editing refused any multi-span text to prevent partial or corrupted writes.

**Phase 3B.2 delivers:**
1. **Word-Level Selection Granularity**: Single-click selection targets distinct human-readable words rather than sprawling multi-line headings.
2. **Deterministic Intra-Word Fragment Merging**: Contiguous intra-word fragments sharing identical geometry, font resource, and baseline are combined into a single atomic word.
3. **Atomic Multi-Span Mutation Engine in Rust**: `replace_text_group` validates all target spans, encodes replacement text with the active font, rewrites the primary target operand, neutralizes downstream sub-span operands (`()`), and preserves text matrices and downstream layout.
4. **All-or-Nothing Safety & Refusal**: Any unsafe condition (mixed font encodings, unrepresentable glyphs, differing content streams) aborts with 0 mutations, 0 history snapshots, and clear user-facing refusal feedback with non-destructive Fill & Sign fallback.

## 2. Architecture & Core Concepts

### A. Separation of Three Core Concepts
1. **Source Span**: The exact physical PDF instruction fragment (`page_index`, `stream_index`, `instruction_index`, `operand_index`, `font_name`, `font_size`, `matrix`, `bytes`).
2. **Visual Group**: The human-scale text presentation unit (`HumanTextGroup`) created by `groupTextSpans()` at word or run granularity.
3. **Mutation Unit**: The transaction passed to `starpdf_replace_text_group` containing the complete list of target `span_id`s to rewrite atomically.

### B. Multi-Span Mutation Execution Strategy
When mutating an intra-word group consisting of targets `[T_0, T_1, ..., T_k]`:
1. **Pre-Flight Validation**:
   - Verify all targets belong to the same page and content stream.
   - Verify all targets use the same font and text state.
   - Verify that the active font can represent 100% of the replacement characters.
2. **Atomicity**:
   - Target $T_0$ operand is updated with the font-encoded bytes of the new text.
   - Targets $T_1 \dots T_k$ operands are neutralized to empty bytes `&[]` (serializing to `()` in `Tj` or `()` in `TJ`).
   - All surrounding operators, text matrices (`Tm`, `Td`), and graphics state remain untouched, preserving all downstream layout.
3. **Re-Edit Durability**:
   - When the mutated PDF is re-extracted, the empty neutralized operands produce 0-length spans that are naturally filtered out.
   - The primary target span represents the updated word, allowing repeated re-editing, undo/redo, and export/reopen cycles with 0 degradation.

## 3. Implementation Details

### Rust Core (`engine/starpdf`)
- `mutation/change.rs`: Added `PdfChange::ReplaceTextGroup { page_index, targets, replacement }`.
- `mutation/text_edit.rs`: Implemented `ContentStreamEditor::replace_multiple_in_stream` to parse, match, and modify multiple operand targets within a single content stream in topological order.
- `mutation/engine.rs`: Implemented `mutate_replace_text_group` in `MutationEngine` with font encoding validation and layout advance compensation.
- `document/document.rs`: Exposed `Document::replace_text_group(page_index, targets, replacement)`.
- `wasm/api.rs`: Exported `starpdf_replace_text_group(handle, page_index, span_ids_js_val, new_text)`.

### TypeScript Frontend & Web Worker
- `src/lib/pdf/starpdf-types.ts`: Added worker request/response types for `replaceTextGroup` and extended `StarPdfTextSpan` with font provenance properties.
- `src/lib/pdf/starpdf-client.ts`: Added `replaceTextGroup` method to `StarPdfDocumentHandle`.
- `public/starpdf.worker.js`: Handled `replaceTextGroup` worker messages with incremental export.
- `src/lib/pdf/commands/text-commands.ts`: Updated `ReplaceTextCommand` and `DeleteTextCommand` to accept `string | string[]` and invoke `replaceTextGroup` when multi-span targets are supplied.
- `src/lib/pdf/grouping/text-grouper.ts`: Implemented word-level boundary detection, font normalization (`isSameFont`), and multi-span atomic editability classification (`EDITABLE_ATOMIC` vs `READ_ONLY_REFUSAL`).
- `src/components/tools/implementations/pdf/PdfContextualToolbar.tsx` & `SmartPdfEditor.tsx`: Wired multi-span targets to toolbar actions, keyboard delete, and unified command history.
