## 2. Pre-Implementation Protocol

Before executing any code modification, the agent must output the **Pre-Implementation Readiness Report** specified in [`docs/AI_WORKFLOW.md`](docs/AI_WORKFLOW.md), including:
- Current Base SHA (`git rev-parse HEAD`)
- Verified list of canonical documents read
- Requirement IDs targeted (`PRD-FR-###`, `PRD-NFR-###`)
- Exact source code files and line ranges inspected
- Grounded description of current behavior vs. target behavior
- Verified assumptions and identified conflicts

### Conflict Stop Condition
If any conflict is detected between canonical documents and codebase reality, the agent **MUST STOP IMMEDIATELY** and report the discrepancy. Do not make arbitrary unilateral decisions.

---

## 3. Implementation Disciplines

1. **Current Code Inspection:** Ground every change in real, inspected source code and tests.
2. **Explicit Implementation Status:** Accurately classify all capabilities as `CURRENT`, `PARTIAL`, `TARGET`, `MISSING`, `DEFERRED`, or `UNSUPPORTED_BY_POLICY`. Never describe planned work as implemented.
3. **Qualified Tests Required:** Every code modification must include corresponding tests (Rust unit/integration tests or TypeScript Vitest/Playwright tests) passing without errors or warnings.
4. **Strangler Migration Only:** Never perform big-bang rewrites. Preserve qualified working systems (`PDF.js` renderer, Playwright suites, existing WASM bridge) until replacement systems pass all qualification gates.
5. **No AI Attribution Trailers:** Never append AI attribution footers, signatures, or metadata tags (e.g., "Generated by AI", "Assisted by Codex") to source files, commit messages, or user-facing artifacts.

---

## 4. Protected Git Operations

- **Explicit Staging Only:** NEVER run `git add -A` or `git add .`. Stage only explicitly touched files by path (`git add path/to/file`).
- **No Destructive Operations:** NEVER run `git reset --hard`, `git clean -fd`, `git stash drop`, or `git rebase` without explicit human authorization.
- **No Force Pushing:** NEVER force push (`git push --force`).
- **Release Track Isolation:** Track A (RC2 qualification on `main`/`arch/integrated`) and Track B (Rust-first architecture redevelopment) must remain strictly isolated. Architecture work must never silently alter or delay the existing release candidate.
